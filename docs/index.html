1. ✖ Why the scene shows nothing (or nothing right) (1): nothing else can be judged while the picture is black or empty
   [add-gltf-result] main.js:27
     GLTFLoader hands over an object holding scene, animations and cameras, not an Object3D: scene.add(gltf) logs "object not an instance of THREE.Object3D" and the model never shows. Fix: scene.add( gltf.scene );

2. ✖ Assets that will not load (2): a missing or mis-cased file is a 404, which the loader reports as a parse error far from the cause
   [asset-missing] main.js:22
     "/textures/crate.jpg" is not in the project (looked in public/textures/crate.jpg, textures/crate.jpg). The server answers with an HTML page, which the loader then fails to parse ("Unexpected token '<'"). Fix: Add the file under public/ (served at /), or fix the path.
   [asset-case] main.js:26
     "/models/Robot.glb" only matches public/models/robot.glb with different capitals: it loads on macOS and Windows and is a 404 on Linux servers and most hosts. Fix: Write the path exactly as the file is named (/models/robot.glb), or rename the file.

3. ✖ Outdated or removed three.js API (3): removed names throw or silently do nothing in the installed release
   [buffer-geometry-alias] main.js:18 (three_fix)
     `BoxBufferGeometry` and friends were renamed; the plain name is the BufferGeometry now.
   [addons-path] x2 index.html:8, main.js:3 (three_fix)
     `three/examples/jsm/...` still works, but `three/addons/...` is the documented path and the one import maps use.

4. ✖ Colours (2): wrong colour spaces make everything look washed out or too dark
   [output-encoding] main.js:7 (three_fix)
     `outputEncoding` was replaced by `outputColorSpace`.
   [texture-colorspace-missing] main.js:23
     Textures loaded with TextureLoader are used as color maps but `colorSpace` is never set, so colors look washed out or too dark. Fix: texture.colorSpace = THREE.SRGBColorSpace; (not for normal/roughness/metalness data maps).

5. ▲ Code that runs but does the wrong thing (4): these are bugs the user will see
   [controls-no-element] main.js:15
     Controls created without a DOM element listen to nothing (since r175 they need one), so mouse and touch do nothing. Fix: new OrbitControls( camera, renderer.domElement ), or call controls.connect( element ) later.
   [controls-damping-no-update] main.js:16
     `enableDamping` only works when controls.update() runs every frame. Fix: Call controls.update() inside the animation loop.
   [rotation-degrees] main.js:19
     Rotations are in radians; 45 here is about 7 turns, not 45 degrees. Fix: Use radians: THREE.MathUtils.degToRad( 45 ) (Math.PI / 4).
   [clip-action-unused] main.js:29
     clipAction() only creates the action; nothing plays until .play() is called on it. Fix: mixer.clipAction( clip ).play();

6. ▲ Performance (3): work per frame and GPU memory decide whether it runs smoothly on a phone
   [pixel-ratio-uncapped] main.js:8 (three_fix)
     `setPixelRatio(devicePixelRatio)` renders up to 9-16x the pixels on high-density screens.
   [alloc-in-loop] main.js:34
     A Vector/Matrix/Quaternion/Color is created with `new` inside the per-frame loop. That produces garbage every frame and causes stutter from garbage collection. Fix: Create the object once outside the loop (const _v = new THREE.Vector3()) and reuse it with .set()/.copy().
   [animation-loop] main.js:33
     `renderer.setAnimationLoop` is the supported loop: it also runs in WebXR and pauses correctly. Fix: renderer.setAnimationLoop((time) => { ...; renderer.render(scene, camera); });

7. ▲ Resize and cleanup (1): leaks and stretched views show up after the first minutes of use
   [no-resize-handling] main.js:6
     A renderer and camera exist but nothing reacts to a resize (no resize listener or ResizeObserver). Fix: On resize: camera.aspect = w / h; camera.updateProjectionMatrix(); renderer.setSize(w, h);

Next:
  1. Call three_fix (dry run), then three_fix write: true for the mechanical renames.
  2. Fix the asset paths (three_assets lists every reference and where it was looked for).
  3. Fix the 'shows nothing' group first, then confirm with three_check (screenshot) or three_inspect (why objects are not visible).
  4. Fix the remaining 1 error(s) by hand; three_api gives the exact names for the installed release.
  5. Call three_review with only_new: true after each change, until no errors are left.
  6. Run three_check on the page (index.html) before you call it done.

Honest limits

  • WebGL 2 in headless Chromium is reliable, also in CI. WebGPU is best effort.
  • Frame times come from software rendering: compare before and after. Draw calls and triangles are exact.
  • The review reads text, not types (three_types adds the type checker). It can be wrong; mark it with three_feedback.
  • No benchmark results are published yet; bench/ has the tasks and the grader.

A FEW THINGS YOU MIGHT WONDER

Good questions.
Clear answers.

Does it need a GPU or a browser window?

No. Most tools read files. The browser tools use headless Chromium with software WebGL 2, which also runs in GitHub Actions.

Which three.js version does it check against?

The one in your node_modules/three. A rule knows the release that removed or renamed an API, so the same line is an error on a new release and a warning on an old one, and a rule whose replacement does not exist yet in your release stays quiet.

Does it work with React Three Fiber?

Yes: rules for useFrame (state set every frame, allocations), objects created in render and render priority, and rules R3F handles itself (dispose, colour space) are skipped.

Does it send my code anywhere?

No. There is no telemetry. Lessons and false-alarm feedback stay in ~/.threesmith, scrubbed of names, paths and code.

Is there one for Godot?

Yes: Godotwright is the same toolkit for Godot 4. Threesmith follows its design.
